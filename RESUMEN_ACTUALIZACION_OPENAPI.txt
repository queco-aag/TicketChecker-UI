✅ ENDPOINTS AGREGADOS (5)
═══════════════════════════════════════════════════════════════

1️⃣  GET /api/v1/premios
   └─ Listar todos los premios
   └─ Requiere: Autenticación (Bearer token) + Rol ADMIN
   └─ Respuesta: Array de premios con todos los detalles

2️⃣  POST /api/v1/premios
   └─ Crear un nuevo premio individual
   └─ Content-Type: application/json (NO requiere archivo)
   └─ Requiere: nombre, descripcion, anio
   └─ Opcional: urlFoto

   Ejemplo de request:
   {
     "nombre": "PlayStation 5",
     "descripcion": "Consola de videojuegos",
     "urlFoto": "https://example.com/ps5.jpg",
     "anio": 2026
   }

3️⃣  GET /api/v1/premios/{id}
   └─ Obtener un premio específico por ID
   └─ Requiere: Autenticación + Rol ADMIN
   └─ Respuesta: Detalles completos del premio

4️⃣  PUT /api/v1/premios/{id}
   └─ Actualizar un premio existente
   └─ Todos los campos son opcionales
   └─ Solo actualiza los campos enviados

   Ejemplo:
   {
     "nombre": "PlayStation 5 Pro",
     "descripcion": "Versión mejorada"
   }

5️⃣  DELETE /api/v1/premios/{id}
   └─ Eliminar un premio
   └─ ⚠️ No se puede eliminar si tiene números asignados
   └─ Respuesta 409 Conflict si hay números asignados

🎯 DIFERENCIAS IMPORTANTES
═══════════════════════════════════════════════════════════════

POST /premios vs POST /premios/cargar-csv
───────────────────────────────────────────────────────────────

POST /premios:
  • Crea UN premio a la vez
  • Content-Type: application/json
  • Body: JSON con nombre, descripcion, urlFoto, anio
  • NO requiere archivo

POST /premios/cargar-csv:
  • Crea MÚLTIPLES premios a la vez
  • Content-Type: multipart/form-data
  • Body: Archivo CSV
  • SÍ requiere archivo
